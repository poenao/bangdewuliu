示例（简化）：

```javascript
import { createUniFetch } from 'uni-app-fetch'
import { useUserStore } from '@/stores/user'

export const uniFetch = createUniFetch({
  loading: { title: '正在加载...' },
  baseURL: 'https://slwl-api.itheima.net',
  intercept: {
    request(options) {
      const store = useUserStore()
      options.header = Object.assign(
        {},
        { Authorization: store.token },
        options.header
      )
      return options
    },
    response({ statusCode, data }) {
      if (statusCode === 401) {
        // 处理跳转到登录（见重定向章节）
      }
      return data
    },
  },
})
```

## 3. 请求拦截与地址重定向

### 3.1 请求拦截器

在请求拦截器中读取 Pinia token 并放到请求头：

```javascript
request(options) {
  const userState = useUserStore()
  options.header = Object.assign({}, { Authorization: userState.token }, options.header)
  return options
}
```

### 3.2 响应拦截器与 401 处理

当响应状态码为 401 时：

1. 通过 `getCurrentPages()` 获取当前页面栈并取得当前页面 `route`。
2. 根据是否是 TabBar 页面选择跳转方式（`switchTab` 或 `redirectTo`/`navigateTo`）。
3. 跳转到登录页并把 `redirectURL` 与 `routeType` 作为 query 传入。

登录页父组件在 `onLoad` 中读取 query，并通过 props 传给登录子组件；登录成功后子组件用 `props.routeType` 与 `props.redirectURL` 执行回跳：

```javascript
// 父页面 onLoad
onLoad((options) => {
  redirectURL.value = options.redirectURL || 'pages/task/index'
  routeType.value = options.routeType || 'switchTab'
})
// 子组件使用 defineProps 接收并 uni[props.routeType]({ url: `/${props.redirectURL}` })
```

常见坑：

- `onLoad` 只能在页面组件使用，子组件要用 `defineProps` 或 `useAttrs`。
- 不要同时定义同名 `ref` 覆盖 `props`。
- 拼接跳转 URL 时注意是否需要前导 `/`，Tab 跳转需要绝对路径。

# 五、面试题（含参考答案）

1. 问：`Pinia` 与 `Vuex` 有哪些主要区别？
   答：Pinia API 更简单，支持组合式 API，无需 mutation，天然支持模块化与 TS 类型推断，使用更直观。

2. 问：如何在 uni-app 中实现 Pinia 数据持久化？
   答：使用 `pinia-plugin-persistedstate` 或自定义 storage（使用 `uni.getStorageSync` / `uni.setStorageSync`）并在创建 pinia 时 `pinia.use(plugin)`，在 store 中通过 `persist.paths` 指定持久化字段。

3. 问：`uni-forms` 的 `validate()` 返回值如何使用？
   答：`validate()` 返回 Promise，校验通过 resolve（可获得表单数据或 true），失败 reject，需使用 async/await 或 then/catch 处理。

4. 问：如何在请求拦截器中统一注入 token？有哪些注意事项？
   答：在请求拦截器内通过 `useUserStore()` 读取 token，合并到 `options.header`。
   注意：拦截器必须能在运行时访问 Pinia，避免循环引用；header 合并时让自定义 header 覆盖默认 header；跨平台 storage 要兼容小程序。

5. 问：当后端返回 401 时如何优雅处理并回跳原页面？
   答：拦截器拿到 `getCurrentPages()` 里的当前页面 `route`，判断是否为 tabBar 页面选择 `switchTab` 或 `redirectTo`，跳转到登录页并把 `routeType` 与 `redirectURL` 作为 query 传入。登录成功后按传入参数回跳。

6. 问：父组件通过 `onLoad` 拿到路由参数后如何传给子组件？
   答：父组件在 `onLoad` 中把参数赋给 `ref`，通过 props 传给子组件。子组件用 `defineProps` 或 `useAttrs` 获取参数；不要在子组件使用 `onLoad`。

# 六、常见问题与排查建议

- 网络请求返回 `code: 1` 且提示 Feign 调用失败：通常是后端微服务未启动或注册中心异常，联系后端或运维排查。
- 子组件拿不到路由参数：检查是否把参数通过 props 传递，确保使用 `defineProps` 或 `useAttrs`。
- 登录后仍无 token：确认登录接口返回结构（token 在哪个字段），以及 Pinia persist 是否正确配置。
- 跳转路径错误（重复拼接）：注意传入的 `redirectURL` 是否带 `/`，跳转时使用绝对路径 `/${redirectURL}`。
